Idea

Four friends write down what they want to have achieved in four years. Each entry can be edited for 30 days, then the capsule is sealed: until the opening day nobody can read the entries, not even their authors. Opening early is only possible if everyone agrees.

Why this topic

The application is small, the rules are not: states, deadlines, a vote and access rights that the server enforces, not just the interface. That is exactly what Spring Boot and Spring Security are for.

Planned engineering

The design is done; implementation follows during the bootcamp.

  • Backend with Java, Spring Boot and Spring Security; MongoDB Atlas as the database through Spring Data.
  • Frontend with React, TypeScript and Vite; it talks to the backend only through the documented REST API.
  • A capsule's state is computed from timestamps instead of being stored, so no background job is needed.
  • Time comes from a replaceable clock, so deadlines of several years can be tested in seconds.
  • Shipped as a Docker image: GitHub Actions tests and builds, Docker Hub holds the image, and Render pulls it from there and runs the application.
  • Static analysis with SonarQube Cloud on every pull request.

How I work

Before the first line of code there are the requirements, an architecture description with a diagram, data model and API draft, and six reasoned decisions. Implementation runs in stages through App-Leitstand: each stage is one pull request with check results.

Status

Concept, architecture and the interface design are done. There is no code yet.

The full case study will follow once the project is finished.
