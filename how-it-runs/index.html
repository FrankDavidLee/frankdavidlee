How my apps run

Three apps of my own, one small server, clear rules. This is how Arbeitseule, heyAppa and my App-Leitstand control center are operated, and why I built it this way.

Building blocks

  • AWS, Frankfurt

    • EC2: one small ARM server for all three apps
    • Caddy as reverse proxy with automatic HTTPS
    • S3 for daily encrypted backups
    • CloudWatch and SNS for two alarms
    • SES for outbound e-mail

  • Cloudflare

    • DNS for both domains
    • Turnstile as bot protection without tracking
    • Email Routing for inbound mail
    • Zero Trust Access and a tunnel in front of the control center

  • GitHub

    • Repositories with one pull request per task
    • Actions: tests on every pull request
    • Deploys only on click, with confirmation
    • A daily check of production
    • Pages for this website

  • AI

    • Claude API for matching and cover letters, with a hard cost limit
    • Claude Code as coding agent
    • MCP: Claude reads tasks straight from the control center

What I pay attention to

  • Approval before production

    Nothing reaches production without approval. Every approval is bound to exactly one revision of the code.

  • Security in layers

    The apps listen on the server itself only, and the control center is not visible on the internet.

  • Back up first, then ship

    Every deploy starts with a backup, and the previous build stays in place as a way back.

  • Privacy from the start

    Servers in the EU, data processing agreements, no tracking cookies.

  • Secrets never in code

    Secrets live on the server and in a password manager only, never in code and never in an AI session.

  • Costs small and visible

    One server, free tiers where possible, a budget alarm.

Deliberate trade-offs

  • One server instead of many

    One server is enough for the current number of users and keeps effort and cost small. It is a single point of failure. That is why there are daily backups, a tested restore and alarms.

  • SQLite instead of a database server

    SQLite is a file: easy to back up and very fast for a few concurrent users. The move to PostgreSQL is prepared, and heyAppa already uses it.

  • The next step when it grows

    A managed database, a second server behind a load balancer, a staging environment before production and infrastructure as code with Terraform.
