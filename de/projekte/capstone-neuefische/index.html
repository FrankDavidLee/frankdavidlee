Capstone im Bootcamp: eine Zeitkapsel für Gruppen mit Java, Spring Boot und React.

Zeitraum
Dez. 2026 – Jan. 2027
Rolle
Konzept und Entwicklung

Idee

Vier Freunde schreiben auf, was sie in vier Jahren erreicht haben wollen. 30 Tage lang lässt sich jeder Eintrag ändern, dann ist die Kapsel versiegelt: Bis zum Öffnungstag kann niemand die Einträge lesen, auch die Verfasser nicht. Früher öffnen geht nur, wenn alle zustimmen.

Warum dieses Thema

Die Anwendung ist klein, die Regeln sind es nicht: Zustände, Fristen, eine Abstimmung und Zugriffsrechte, die der Server durchsetzt und nicht nur die Oberfläche. Genau dafür sind Spring Boot und Spring Security da.

Geplante Technik

Der Entwurf steht, die Umsetzung folgt im Bootcamp.

  • Backend mit Java, Spring Boot und Spring Security; MongoDB Atlas als Datenbank über Spring Data.
  • Frontend mit React, TypeScript und Vite; es spricht nur über die dokumentierte REST-Schnittstelle mit dem Backend.
  • Der Zustand einer Kapsel wird aus Zeitpunkten berechnet statt gespeichert. So braucht es keinen Hintergrundjob.
  • Die Zeit kommt aus einer austauschbaren Uhr, damit sich Fristen von Jahren in Sekunden testen lassen.
  • Auslieferung als Docker-Image: GitHub Actions testet und baut, Docker Hub hält das Image, Render holt es von dort und betreibt die Anwendung.
  • Statische Analyse mit SonarQube Cloud bei jedem Pull Request.

Arbeitsweise

Vor der ersten Zeile Code stehen die Anforderung, eine Architekturbeschreibung mit Zeichnung, Datenmodell und Schnittstellen-Entwurf und sechs begründete Entscheidungen. Die Umsetzung läuft in Etappen über den App-Leitstand: jede Etappe ein Pull Request mit Prüfergebnissen.

Stand

Konzept, Architektur und der Entwurf der Oberfläche stehen. Code gibt es noch nicht.

Die vollständige Fallstudie folgt nach Abschluss des Projekts.
